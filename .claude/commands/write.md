argument-hint: 소재: … , 한줄 메모: … [, 제목: …] [, 큰 틀: 소주제1 > 소주제2 …] [, 사진 없이 테스트]
---

입력: $ARGUMENTS

`docs/writing-rules.md`(정본)와 `data/blogger-profile.md`를 기준으로 아래 순서대로 진행한다.

## 1. 입력 확인
- 입력에서 `소재`, `한줄 메모`를 찾는다. 선택 항목인 `제목`(지정 시 그대로 쓰되 25~32자·특수문자 규칙을 어기면 고칠 안을 묻는다)과 `큰 틀`(소주제 순서)도 찾는다.
- 소재나 메모가 없으면 질문부터 한다.
- "사진 없이" 또는 "테스트"가 있으면 `"test": true` 초안으로 짧게 쓴다.

## 2. 프로필 빈칸 확인
`data/blogger-profile.md`에서 이번 글에 필요한 항목이 비어 있으면, 글을 쓰기 전에 한 번에 묶어서 묻는다:
화자 톤 → 실패 사례·경험담 → 자격·경력 → 블로그 URL → 첫 타깃 키워드 → 콘텐츠 비중·발행 주기 → 타깃 독자·발행 시간대 → 목표 2 → 투자 면책 문구.
답을 받으면 프로필에 기록한다. 답하지 않은 항목은 비워 둔다.

## 3. 사진
- `input/photos/_mosaic/`의 사진을 Read 도구로 직접 본다. `input/photos/`에만 있고 `_mosaic`에 없는 사진은 쓰지 않는다. 대신 모자이크가 필요하다고 알린다.
- 가려지지 않은 개인정보(5-7 목록)가 보이면 그 사진을 빼고 알린다.
- 사진에서 확인되는 사실만 쓴다. 이야기 순서대로 배치한다.

## 4. 수치 확인
- 글에 들어갈 수치마다 6절 규칙을 적용한다. 웹 검색으로 공식 기관 자료를 확인하고 URL과 기준일을 남긴다.
- 확인하지 못한 값은 `[[확인필요: …]]` 마커로 남긴다.

## 5. 작성
- 직전 후킹 패턴을 `drafts/`의 가장 최근 draft.json에서 확인하고, 다른 패턴을 고른다.
- `data/analysis-latest.md`가 있으면 읽고, 상위 글 교집합(제목 유형·단어)을 제목 유형(`title_hook`)과 키워드 후보에 반영한다 (규칙 8절). 반영했으면 검수 보고에 근거를 적는다.
- `drafts/YYYYMMDD-<영문슬러그>/draft.json`과 `review.md`(7-2 형식)를 쓴다.

## 6. 형식 검사
- `node scripts/lint_draft.js <draft.json>`을 실행한다.
- 오류는 형식만 고친다. 고치려고 사실을 추가하지 않는다. 오류가 없어질 때까지 반복한다.
- 확인필요 마커가 남아 있으면 여기서 멈추고, 사용자에게 값을 묻는다. 임시저장하지 않는다.

## 7. 임시저장
- `node scripts/naver_draft.js <draft.json>`을 실행한다. 로그인 세션이 없다는 오류가 나면 사용자에게 `! node scripts/naver_login.js`를 직접 실행해 달라고 한다. 비밀번호는 사람이 브라우저에 입력한다.
- 실패하면 `node scripts/draft_status.js <draft.json>`로 단계를 확인하고 `debug/` 스크린샷·HTML을 본다. 원인이 셀렉터라면 `scripts/lib/selectors.js`만 고친다. 다시 실행하기 전에 사용자에게 한 번 묻는다. 초안은 다시 쓰지 않는다.
- 발행 가드 오류가 나면 즉시 멈추고 보고한다. 가드를 고치거나 우회하지 않는다.

## 8. 보고

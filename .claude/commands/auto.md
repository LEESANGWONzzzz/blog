입력: $ARGUMENTS

`docs/writing-rules.md`(정본), `data/blogger-profile.md`, `.claude/commands/write.md`를 따른다.
사람에게 묻지 않고 끝까지 진행하되, 아래 "멈춤 조건"에 걸리면 그 자리에서 멈추고 이유를 보고한다.

## 1. 주제 정하기
- 입력에 주제가 있으면 그대로 쓴다.
- 입력에 GPT 작업 A 결과가 있으면 그중에서 고른다.
- 입력이 비어 있으면 웹 검색으로 최근 7일 안의 정부·공공기관 보도자료를 찾아 고른다 (출처는 보도자료 본문 페이지만).
- 고르는 기준 (순서대로): 신청 마감·시행일이 확정됐고 가까운 것 → 출퇴근 직장인의 월급·지출에 직접 영향 → 프로필의 5개 분야 비중 → 최근 `drafts/` 7일 안에 같은 주제가 없을 것.
- 정부안·예고 단계는 "확정 아님"을 제목과 본문에 분명히 쓸 수 있을 때만 고른다.

## 2. 수치 확인 → `drafts/<글폴더>/facts.md`
- 글에 들어갈 수치·날짜·조건마다 공식 기관 페이지를 직접 열어(WebFetch) 확인한다.
- 입력에 GPT 작업 C 결과가 있으면 출발점으로 쓰되, 각 값의 출처 URL을 직접 열어 대조한다. 다르면 공식 페이지 값을 따르고 차이를 facts.md에 적는다.
- `admin.korea.kr`처럼 관리자용으로 보이는 주소는 `www.korea.kr` 주소로 바꿔 열리는지 확인한다. URL 끝의 `utm_*` 추적 문구는 지운다.
- 형식: `| 항목 | 값 | 기준일·적용기간 | 출처 기관 | URL | 직접 확인 여부 |`
- 확인 못 한 값은 글에 쓰지 않거나 `[[확인필요: …]]`로 남긴다.

## 3. 이미지
- `write.md` 3번과 규칙 5-8을 따른다. 기본 구성: 표지 1 + 소제목 요약 카드 2~4 + 마무리 1 (사진·공식 자료가 있으면 그만큼 줄인다).
- 이미지 속 숫자는 facts.md에서 "직접 확인"된 값만 쓴다.
- 생성 후 Read 도구로 한 장씩 열어 철자·숫자를 확인하고, 틀린 것만 다시 만든다 (최대 2회).

## 4. 글쓰기·검사·임시저장
- `write.md` 5~7번을 그대로 진행한다 (draft.json, review.md, lint, `node scripts/naver_draft.js`).
- review.md에 facts.md 대조 결과와 이미지 목록(종류·출처·확인 결과)을 포함한다.

## 5. 보고 (짧게)
- 고른 주제와 이유 한 줄, 제목, 이미지 n장(생성/공식/사진), 확인 못 한 값, 임시저장 결과, `publish_checklist.txt` 경로.
- "임시저장함에서 확인 후 직접 발행하세요."

## 멈춤 조건 (여기서 멈추고 보고)
- 확인필요 마커가 남음 → 어떤 값인지와 확인 방법을 보고. 임시저장하지 않는다.
- 이미지 생성 종료 코드 3(API 키 없음) → `image_prompts.md`를 안내. 이미지가 준비되면 이어서 진행.
- 발행 가드 오류 → 즉시 중단. 가드를 고치거나 우회하지 않는다.
- 오늘 이미 자동 임시저장을 2건 했으면 → 새로 저장하지 않고 초안까지만 만든다.

# UNBOXED 자동 등록 폴더 — Claude Code 작업 지시

이 폴더는 네이버 커머스API로 상품을 등록하는 프로그램이다. 사용자가 상품을 한 줄로 보내면 아래 순서로 **조사 → 작성 → 엑셀 추가 → 미리보기 → (사용자 확인 후) 등록**까지 진행한다.

## 0. 자동 등록 작업 흐름

입력 예시: `나이키 ACG 라바 플로우 써마 핏 ADV 재킷 IR2339-010` (+ 매입가, 남길 금액 또는 판매가)

1. **조사**: 모델코드를 웹검색해 공식 상품명, 컬러, 성별, 소재, 기능, 제조국, 상품 종류를 확인한다 (아래 규칙 1장).
2. **매입가 확인**: 매입가와 남길 금액(또는 판매가)이 없으면 등록 전에 물어본다. 추측해서 가격을 정하지 않는다.
3. **작성**: 상품명(3장), 판매가(2장), 관련 태그 10개(3-4절), 상세 문구(3-5절의 상품 블록)를 만든다.
4. **사진 확인**: `이미지` 폴더에서 모델코드로 시작하는 파일(예: `IR2339-010_1.jpg`)을 찾는다. 없으면 사용자에게 사진을 넣어 달라고 하고 멈춘다.
5. **카테고리**: `python unboxed_uploader.py category 단어` 로 카테고리ID를 찾는다. 후보가 여러 개면 가장 구체적인 하위 카테고리를 고르고 사용자에게 알린다.
6. **엑셀 추가**: 아래 키를 가진 JSON 파일을 `결과` 폴더에 만들고 `python add_row.py 그파일.json` 으로 products.xlsx 에 한 줄 추가한다.
   키: 상품명, 모델코드, 판매가, 매입가, 목표순수익, 재고, 카테고리ID, 브랜드, 고시유형(SHOES/WEAR), 컬러, 소재, 사이즈옵션("270:1, 275:2"), 대표이미지, 추가이미지, 상세HTML파일, 상세텍스트, 태그, 전시상태
   - 상세텍스트에는 3-5절 상품 블록 문구를 줄바꿈 그대로 넣는다 (대괄호 제목 줄은 빼고 내용만).
   - 이미지 칸을 비워 두면 add_row.py 가 이미지 폴더에서 자동으로 채운다.
   - 전시상태는 비워 둔다 (= 전시중지). 사용자가 ON을 원할 때만 ON.
   - 사이즈·재고를 모르면 사용자에게 묻는다.
7. **미리보기**: `python unboxed_uploader.py preview` 를 실행하고 상품명, 판매가, 순수익, 이미지 수, 오류 여부를 짧게 보고한다.
8. **등록**: 사용자가 "올려줘/등록해" 라고 확인한 뒤에만 `python unboxed_uploader.py upload --confirm` 을 실행한다. 확인 없이 등록하지 않는다.
9. **결과 보고**: 상품번호, 전시중지 상태라 판매자센터에서 확인 후 전시해야 한다는 것을 알린다. 오류면 응답의 invalidInputs 를 보고 원인을 찾아 고친 뒤 다시 미리보기부터 한다.

**보안**: config.ini 의 client_id/client_secret 값을 읽어서 출력하거나 대화에 쓰지 않는다. 토큰도 출력하지 않는다.
**이미 등록한 상품**: products.xlsx 에 이전 줄이 남아 있으면 다시 등록될 수 있다. 등록이 끝난 줄은 사용자 확인 후 지우거나, 등록 전에 이번에 올릴 줄만 남아 있는지 확인한다.

## 0-1. 상세페이지 공통 블록 (NEW & BEST·톡톡 링크 등)

상세페이지 = **상세_상단.html + 상품 블록 + 상세_하단.html**. 프로그램이 등록할 때 자동으로 위아래를 붙인다.
공통 블록(브랜드 배너, 컬렉션, NEW & BEST 카드별 상품 링크, 톡톡 링크, 고객 가이드 이미지)은 이미 판매자센터에서 잘 만든 상품에서 가져온다.

**처음 한 번 (또는 공통 블록을 바꿀 때)**
1. 사용자에게 공통 블록이 제대로 들어간 상품번호를 묻는다 (예: 13882203454 클럽 퓨추라 FZ0657-010).
2. `python unboxed_uploader.py fetch-detail 상품번호` → `결과/상세_상품번호.html` 저장.
3. 그 HTML을 읽고, 그 상품에만 해당하는 부분(상품명·스타일 코드·Detail Cut 사진·설명·체크리스트·스펙·착용컷)의 **앞부분 전체**를 `상세_상단.html`, **뒷부분 전체**를 `상세_하단.html`로 저장한다. 공통 블록의 `<a href>` 링크와 이미지 주소는 한 글자도 바꾸지 않는다.
4. 어디서 나눴는지(상단 끝/하단 시작에 있는 이미지나 문구) 사용자에게 보여주고 확인받는다.

**이미 올린 상품에 공통 블록 붙이기**
1. `python unboxed_uploader.py fix-detail 번호1 번호2 ...` (미리보기: `결과/수정전_번호.html`, `수정후_번호.html` 저장)
2. 사용자가 확인하면 `python unboxed_uploader.py fix-detail 번호1 번호2 ... --confirm`
3. 이미 공통 블록이 있는 상품은 자동으로 건너뛴다.
4. 수정 API(`PUT /v2/products/channel-products/{번호}`)는 실제 호출로 아직 확인하지 않았다. 처음엔 한 상품만 --confirm 으로 해 보고, 판매자센터에서 상세페이지를 확인한 뒤 나머지를 진행한다.

**NEW & BEST 상품을 바꿀 때**: 상세_상단/하단.html 안의 해당 카드 `<a href="...products/번호">` 와 이미지를 바꾼 뒤, 모든 상품에 다시 반영하려면 사용자와 상의한다 (fix-detail 은 이미 감싼 상품은 건너뛰므로 별도 작업이 필요).

# UNBOXED 상품명·판매가 작업 규칙

UNBOXED는 나이키·뉴발란스 아울렛 상품을 사서 네이버 스마트스토어에 되파는 스토어다. 사용자는 주로 **상품명과 판매가**를 정해달라고 한다. 새 상품을 받으면 아래 규칙대로 처리한다.

## 1. 작업 흐름

입력 예시:

```
[국내매장판] 나이키 ○○ 남성 ○○ 모델코드
매입가 61000
만원 남겨줘   (또는 "판매가 228000"처럼 판매가를 직접 줌)
```

처리 순서:
1. 모델코드를 웹검색해 실제 스펙을 확인한다: 정식 상품명, 컬러, 성별, 소재, 정가. 사용자 설명만 믿지 않는다.
2. SEO 상품명을 만든다 (3장).
3. 목표 순수익이 있으면 판매가를 역산한다. 판매가를 받았으면 순수익을 계산한다 (2장).
4. 결과는 **상품명, 판매가, 관련 태그 10개**를 준다 (태그는 3-4절). 상세페이지 HTML이나 이미지는 만들지 않는다 (2026.08부터 중단).
5. 판매가가 같은 코드의 경쟁 판매처 시세보다 높으면 반드시 알린다.

## 2. 순수익·판매가 계산 (스마트스토어 전용)

- 네이버 수수료 6.63% = 주문관리 3.63% + 매출연동 3.00% (2026.08 정산 데이터 기준. 정책이 바뀌면 다시 확인한다)
- 배송비 수입 3,500원 (판매가에 더해짐)
- 고정비 3,066원 = 박스 476 + 스티커 90 + 택배 2,500
- 총결제액 = 판매가 + 3,500
- 순수익 = 총결제액 − 총결제액 × 6.63% − 3,066 − 매입가
- 역산한 판매가는 **1,000원 단위로 올린다**. 올린 뒤에도 목표에 못 미치면 1,000원 더 올린다.
- 크림(KREAM), 포이즌(POIZON), 당근마켓은 수수료 구조가 달라서 이 공식을 쓰면 안 된다.

```python
import math

FEE, SHIP, FIXED = 0.0663, 3500, 3066

def net_profit(price, cost):
    total = price + SHIP
    return total - total * FEE - FIXED - cost

def solve_price(cost, target):
    breakeven = (target + FIXED + cost) / (1 - FEE) - SHIP  # 올림 전 이론상 판매가
    p = math.ceil(breakeven / 1000) * 1000
    if net_profit(p, cost) < target:
        p += 1000
    return p, round(net_profit(p, cost)), round(breakeven)

# 검증: solve_price(131904, 10000) -> (152000, 10220, 151764)
```

## 3. SEO 상품명 규칙

### 3-1. UNBOXED 규칙
- 맨 앞에는 항상 `[국내 매장판]`을 붙인다 (2026.09 규칙 변경). 다만 사용자가 `[백화점 매장판]`처럼 다른 표기를 주었거나, "국내발송"처럼 매장판인지 분명하지 않으면 확인을 요청한다.
- 길이는 **띄어쓰기를 포함해 50자를 넘지 않게** 한다 (사용자 지정). 결과에 띄어쓰기 포함 글자 수를 적는다.
- 순서: 브랜드 → 시리즈 → 모델코드 → 상품유형 → 컬러 → 소재 → 사이즈 → 성별 → 속성
- 정보를 주는 키워드만 쓴다. 동의어 나열, 홍보 문구, 중복 표현("운동화 러닝화", "남자 조끼 베스트")은 뺀다.
- 사용자 문구를 그대로 옮기지 않는다. 검색으로 확인한 핵심 스펙(소재, 기능, 컬러)은 더하고, 불필요한 단어는 자른다.
- 컬러를 확인하지 못했으면 **추측해서 넣지 않는다**. 컬러 없이 완성하고 택 확인을 요청한다.
- 한 코드에 여러 컬러가 함께 올라오면(예: IB2976-235/297) 모델코드 앞부분은 한 번만 쓰고(IB2976), 남는 글자에 다른 키워드를 넣는다. 컬러별로 근거가 얼마나 확실한지 알린다 (2026.10 사용자 지정).
- 사용자가 준 머리말 `[나이키 코리아]`, `[오늘출발]` 등은 `[국내 매장판]`으로 바꾼다 (공식 판매처 오해, 배송 홍보 문구).
- 컬러명 "세일(Sail)"은 할인 문구로 오해받으므로 상품명에서는 아이보리 등으로 바꾼다.
- 사이즈(M, 2XL 등)는 옵션으로 등록하고 상품명에서 뺀다. 단일 재고면 넣어도 된다.
- 성별·컬러·기장(숏)·"경량"·"발편한"·"가벼운"처럼 확인하지 못한 정보는 넣지 않는다.
- 다른 상품명(예: 코트 비전에 "에어포스")을 끌어오지 않는다.

### 3-2. 네이버 쇼핑 검색 SEO 가이드 (사용자가 준 네이버 문서 기준)
- 상품명 기본 구조: 브랜드 + 속성 + 카테고리 + 사이즈 + 시즌성. 브랜드와 카테고리는 꼭 넣는다.
- 상품명이 불필요하게 길면 적합도 점수가 떨어진다. 검색품질 체크는 50자 이내를 권장한다.
- 키워드는 네이버 쇼핑 자동완성·연관검색어를 참고해서, 상품 특성에 맞는 것을 1~2개만 넣는다.
- 감점·제재 대상:
  - 검색에 비권장되는 특수문자: `? ! ( )`, ★, ▶
  - 혜택·수식 문구: 할인, 세일, 무료배송, 당일발송, "인기 1위"
  - 브랜드명 3번 이상, 사용자 그룹(20대, 30대) 2번 이상, 날짜(4월, 5월) 2번 이상
  - 이미테이션 표현: ~스타일, ~st, 관련 없는 유명 상품명
  - 셀러명·몰명 넣기, 카테고리어 반복
  - 실제 상품과 관련 없는 키워드
- 렌탈·해외·중고 여부는 상품명에 쓰지 않는다. 상품 상태 설정으로 표시하면 자동 노출된다.
- 색상·사이즈는 옵션으로 정확히 등록하면, 상품명에 넣지 않아도 그 검색어로 노출된다.

### 3-4. 관련 태그 (상품마다 10개)
- 사용자가 보여준 실제 스마트스토어 "관련 태그" 예시:
  `#시선강탈데일리룩 #경량패딩점퍼 #국내매장정품 #남친선물 #남편선물 #나코탭 #아들선물 #매일입고싶은 #가볍고세련된 #조카선물`
- 이 형식처럼 `#` 붙인 붙여쓰기 태그로 10개를 준다. 아래를 섞는다.
  - 선물 대상: 남친선물, 남편선물, 아들선물, 여친선물, 아내선물, 딸선물, 조카선물 등 (상품 성별에 맞게)
  - 감성·스타일 문구: 시선강탈데일리룩, 매일입고싶은, 가볍고세련된처럼 짧은 수식형 표현
  - 상품 특성이 들어간 복합어: 경량패딩점퍼, 레트로스니커즈처럼 속성 + 상품유형
  - `#국내매장정품`
- 확인하지 않은 기능(발편한, 방수 등)이나 할인·무료배송 같은 혜택 문구는 넣지 않는다.
- 태그 사전 등록 여부는 등록 화면 "검색 적용 태그 확인"에서 사용자가 확인한다.

### 3-5. 상세페이지 (2026.11 개편, 레퍼런스: 간디슈즈 상세페이지)
상세페이지는 **공통 블록(한 번 만들어 모든 상품에 재사용하는 이미지)** + **상품 블록(상품마다 바뀌는 부분)** 으로 나눈다. 상품 요청 때는 상품 블록만 텍스트로 준다.

페이지 순서:
1. [공통] 컬렉션 배너 — "THE COLLECTION 한눈에 보는 나이키 베스트셀러", 카테고리 카드 6~7개(작은 문구 + "나이키 ○○ 모음" + 보기>> + 사진), 카드마다 카테고리 링크
2. [공통] 신뢰 영상/이미지 — 매장 박스·택 실물 + "CHECK 국내 매장판 정품"
3. [공통] 상담 운영 시간 — 톡톡 링크, 평일 시간, 점심, 휴무
4. [공통] 스토어 소개 — 검정 배경, 로고, UNBOXED, 정품 배지, 한두 줄 소개
5. [상품] 타이틀 + 스타일 코드
6. [상품] Detail Cut — 직접 촬영 2×2: ①갑피 ②밑창·쿠셔닝 ③측면 로고 ④택 라벨(스타일코드·사이즈·제조국이 보이게) + 색상 차이 안내 문구
7. [상품] 헤드라인 1줄 + 설명 2~3문장 + ✓ 체크리스트 4~6개 (나이키 코리아 공식 설명 기준)
8. [상품] 스펙 표 BRAND / STYLE / COLOR / MADE IN
9. [상품] 착용컷·제품 전체컷 (직접 촬영 권장)
10. [공통] NOTICE + 배송 시스템(주문확인 → 상품입고 → 검수 → 출고 → 배송완료, 출고 마감 시간)
11. [공통] 서비스 및 상품 안내(사이즈·색상 차이·제조 정보) + 배송 안내(택배사, 배송비, 반품 주소)
12. [공통] 교환·반품 안내(접수 기한·방법, 진행 순서, 유의사항, 불량 처리) + 교환·반품 제한(단순 변심 불가 사유, 포장 방법 그림)
13. [공통] NEW & BEST — 인기 상품 배너 6~7개(이탤릭 한 줄 문구 + 상품명 + 보러가기)

상품 블록 출력 형식:
```
[타이틀]
{나이키 코리아 공식 한국어 상품명}
{스타일 코드}

[Detail Cut 촬영 목록]
① 갑피 ② 밑창·쿠셔닝 ③ 측면 로고 ④ 택 라벨
*본 상품 이미지는 촬영 환경(조명, 카메라) 및 사용하시는 모니터·스마트폰 해상도에 따라 실제 색상과 다소 차이가 있을 수 있습니다.

[헤드라인]
{한 줄}

[설명]
{2~3문장}

[체크리스트]
✓ {공식 기능·소재 4~6개}

[스펙]
BRAND Nike | STYLE {코드} | COLOR {공식 컬러 한글} | MADE IN {제조국}
```

- 헤드라인·설명·체크리스트는 나이키 공식 페이지 내용만 근거로 쓰고, 문장은 직접 다듬는다(공식 문구 통째 복사는 피한다). 공식 페이지에 없는 기능, "이전 모델 대비" 비교, "발편한" 같은 표현은 쓰지 않는다.
- 이 코드의 공식 페이지가 없으면 번호가 한 자리 다른 같은 모델이나 같은 모델 다른 컬러의 공식 정보를 쓰고 맨 끝에 알린다. MADE IN을 확인 못 하면 "택 확인"으로 둔다.
- 레퍼런스에 있던 "매장 AS", "유통 경력 15년", "CCTV 녹화", "100% 정품"(근거 표시 없이), 우체국 택배·배송비 3,300원·오전 11시 마감 같은 수치는 다른 스토어의 사실이다. UNBOXED 사실(배송비 3,500원, 출고 마감 등)로 바꾸고, 확인 안 된 것은 쓰지 않는다.
- 나이키 공식 이미지·영상은 저작권 문제가 생길 수 있어 직접 촬영본을 우선한다.
- "아울렛", "이월재고"는 쓰지 않는다.

## 4. 응답 형식

### 4-1. 상품 등록 요청 (기본, 2026.10 사용자 지정)
- 출력은 **상품명 / 판매가 / 관련 태그 10개 / 상세페이지 상품 블록(3-5절)** 네 가지만. 계산표, 근거 설명, 정보 구분, 3블록, 출처 목록은 쓰지 않는다.
- 검증(웹검색, 계산)은 그대로 하되 보여주지 않는다.
- 예외: 판매가가 경쟁 시세보다 높거나, 컬러·성별을 확인하지 못해 뺐을 때만 맨 끝에 한 줄로 알린다.

### 4-2. 그 밖의 질문 (사실 확인이 필요한 경우)
1. 요청 분해
2. 정보 구분: 확인된 사실 / 근거 있는 추론 / 확인되지 않은 가정 / 의견 / 확인 불가
3. 결과
4. 끝에 아래 세 블록을 붙인다.

```
[명확한 답변]
바로 쓸 수 있는 답변

[신뢰도]
0.0~1.0 점수와 이유 한 줄

[확인할 점]
가정, 모르는 정보, 충돌하는 근거, 직접 확인할 내용
```

- 사실·수치·출처를 지어내지 않는다. 확인하지 못했으면 "확인 불가"라고 쓴다.
- 신뢰도는 말투가 아니라 근거의 품질로 매긴다. 0.8 미만이면 가장 약한 주장을 다시 검토한다.
- (4-2 형식일 때) `[확인할 점]`에는 1,000원 올림 전의 이론상 판매가(손익분기)를 적는다.
- 시세 경고 예시: "KREAM 즉시구매가가 약 98,000원이라 113,000원은 경쟁력이 낮을 수 있음"
- 판매가와 시세를 비교할 때는 검색 시점에 판매처가 표기한 정보에 의존한다. 실물 택과 다르면 택을 우선한다.
